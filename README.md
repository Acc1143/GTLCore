## 我改了什么

### ME 样板总成

把 `gtceu:me_pattern_buffer` 的样板槽位从默认 `27` 格改到了 `108` 格，也就是 `12 x 9`。

具体干的破事：

- 给 `MEPatternBufferPartMachine` 加 Mixin。
- 构造逻辑里把样板槽位 `27 -> 108`。
- GUI 创建逻辑里把行数 `3 -> 12`。
- 匿名终端库存那里也一起补了 `27 -> 108`，不然界面和实际库存容易对不上。

### ExtendedAE 扩展样板供应器

这个东西原来就通过配置 `exPatternProvider` 从外面读容量，默认还是 `36`，不是硬改成别的鬼数字。

现在保留这个逻辑：

- 默认 `36`。
- 配置范围 `36..360`。
- 方块版和面板版扩展样板供应器都继续读取这个配置。

顺手修了一个 GUI 显示 bug：槽位变多以后，原本的界面不会跟着变高，玩家背包和返回物品栏会被样板槽顶烂。

现在 GUI 会按实际配置动态算行数：

- `rows = ceil(exPatternProvider / 9)`
- `offset = (rows - 4) * 18`

也就是说，你配多少格，它就按 9 列算多少行，然后把下面那堆用户栏、返回物品栏往下挪。不是固定 108，也不是拍脑袋瞎挪。

### 多方块输入仓隔离

修了一个很阴间的多方块配方问题：大型多方块机器吃多种流体的时候，就算你把输入仓隔离打开了，原来的流体并行倍率计算还是会把全机器的流体凑一块看。

结果就是 A 输入仓有一种液体，B 输入仓有另一种液体，机器也敢把它们当成同一个配方的输入。说白了就是隔离按钮看着挺努力，底层计算在那装死。

现在改成这样：

- 已经匹配到某个隔离输入组的配方，只按这个输入组算流体并行。
- 还没绑定输入组的时候，逐个输入组单独算能跑几并行，然后取能跑的最大值。
- 非隔离输入仓还是按同一个池子处理，想混就混，别把正常合仓也一刀切了。
- 未消耗流体也只在同一个输入组里检查，不再跨仓东拼西凑。

顺手把输入仓隔离默认打开了。新放下来的 GTCEu 输入总线、双输入仓，还有 gtmthings 的巨型输入总线，默认就是隔离开启。

已经在存档里保存过开关状态的仓，不会被这次默认值硬掰回来。你之前手动关了，那就还是关着，锅自己背。

## 用法

把打出来的这个 `gtlcore-1.1.1-build_11.jar` 扔到 `GregTech-Leisure-CEu-1.4.5` 里面。

然后替换掉原来的 `gtlcore-1.1.1-build_11.jar`。

说白了就是别他妈新建一个奇怪名字的 jar，也别两个 gtlcore 一起塞进去。就替换原来的那个。

## 这玩意儿怎么实现的

靠 Mixin。

说白了就是 GTL 在运行时对 GTCEu、AE2、ExtendedAE 的类动手脚，把原来写死的常量、GUI 样式、槽位布局给改掉。没重新编 GTCEu，也没重新编 ExtendedAE，就是在 GTL 这边注入修改。
